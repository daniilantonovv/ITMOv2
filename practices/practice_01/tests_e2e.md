# E2E-проверки

Окружение: сервис запущен через `uvicorn app.api:app` в staging, LLM — тестовый аккаунт провайдера с timeout 10 с; запросы от имени ревьюера через `curl`/HTTP-клиент.

| Сценарий пользователя | Предусловия | Действие | Наблюдаемый результат | Evidence |
|---|---|---|---|---|
| Позитивный (E2E-01, US-1): ревьюер получает разбор учебного PR | `GET /health` → 200; настроен LLM; master prompt `review_v1` | `curl -s -X POST $URL/api/reviews -H 'Content-Type: application/json' --data "$(jq -Rs '{diff: .}' TRAINING_PR.diff)"` | 200 за ≤ 12 с; JSON с `summary`, 1–3 `risks`, `checks`; каждый `evidence` находится `grep -F` в `TRAINING_PR.diff`; среди рисков есть SEC-1 | Сохранённый ответ + вывод `grep -F` по каждому evidence |
| Негативный (E2E-02, US-3): пустой запрос | Сервис запущен | `curl -s -o /dev/null -w '%{http_code}' -X POST $URL/api/reviews -H 'Content-Type: application/json' -d '{}'` | `422`; в логе запрос со статусом 422 и без обращения к LLM | Код ответа + строка лога OBS-1 |
| Граничный (E2E-03, US-3): diff на границе лимита | Сервис запущен | Отправить diff ровно 20 000 символов, затем 20 001 символ | Первый запрос — 200, второй — 413 за < 1 с; для второго нет исходящего вызова LLM | Коды ответов + счётчик вызовов LLM в метриках |
| Негативный (E2E-04, US-2 + US-4): diff с канареечным секретом | Канарейка `ghp_CANARY…` зарегистрирована в аудите провайдера | Отправить diff, где добавлена строка с канарейкой | 200; в логах сервиса и в журнале запросов провайдера канарейки нет, есть `[REDACTED]` | Выгрузка журнала провайдера + `grep` по логам |
| Негативный (E2E-05, US-3, REL-1): провайдер LLM деградировал | В staging между сервисом и LLM стоит fault-injection прокси (Toxiproxy): задержка 15 с, затем обрыв соединения | `curl -s -w "\n%{http_code} %{time_total}" -X POST $URL/api/reviews ...` с небольшим diff — сначала с задержкой, затем с обрывом | Задержка: `504` за ≤ 11 с; обрыв: `503`; тело — короткое сообщение без текста diff и без текста ошибки провайдера | Код, `time_total`, тело ответа + строка лога OBS-1 |

## Как использовали AI

- Строка в [`prompts.md`](prompts.md): P1-02 — проверки из `checks` (SEC-1, API-1) перенесены в E2E-03 и E2E-04; E2E-05 добавлен по RAG-проверке покрытия ([`../practice_02/prompts.md`](../practice_02/prompts.md) E2-05): у REL-1 не было E2E.
- Что проверили и исправили сами: команды `curl` составили и проверили сами на корректность кавычек (`jq -Rs` упаковывает diff в JSON-строку); критерий «evidence находится в diff» добавили после расхождения номеров строк в P1-02.
