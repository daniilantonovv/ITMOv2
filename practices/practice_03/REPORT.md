# ДЗ 3: локальный помощник по проекту

## Железо и версии

| | |
|---|---|
| Машина | MacBook, Apple M4 (10 ядер), 16 GB unified memory |
| ОС | macOS 26.6.2 |
| Сервер моделей | Ollama 0.34.4 (приложение, `brew install --cask ollama-app`) |
| Агент | OpenCode 1.18.33 |
| Python | 3.10+, только стандартная библиотека |

## Модель

| | |
|---|---|
| ID | `qwen3.5:4b` (Ollama digest `2a654d98e6fb`) |
| Параметры | 4.7B, архитектура qwen35 |
| Квантизация | Q4_K_M, файл ~3.4 GB |
| Возможности | tools, thinking, vision; лицензия Apache 2.0 |
| Собранные модели | `itmo-local` (`lab/Modelfile`, ctx 4096) и `itmo-agent` (`lab/Modelfile.agent`, ctx 65536) |
| Память при работе | ~3.2 GB при ctx 4k, ~5.5 GB при ctx 64k, 100% GPU |

**Почему эта модель.** На 16 GB unified memory модель + KV-кэш на 64k должны оставлять место под систему и IDE. 4B в Q4_K_M занимает ~5.5 GB даже с 64k контекстом, умеет tool calling (без этого OpenCode не может читать файлы) и неплохо пишет по-русски. Более крупные модели (9B) с 64k контекстом заняли бы большую часть памяти; меньшие (0.8B/2B) не пробовал — 4B уже уложилась по скорости (~30 tok/s).

## Длина контекста

- `itmo-local` — **4096**: для прямого чата (README + вопрос ≈ 100–170 токенов) этого с запасом.
- `itmo-agent` — **65536**: системный промпт OpenCode с описанием инструментов ≈ 5–6k токенов. При 4096 Ollama **молча обрезает** запрос до ~2k токенов (видно в `~/.ollama/logs/server.log`: `truncating input prompt`), и модель теряет инструкции. Поэтому для OpenCode отдельная модель с 64k.

## Что настроено

- `lab/Modelfile` — temperature 0.2, top_p 0.9, `num_predict 512`, русский system prompt с правилами «нет данных → так и скажи» и «ложная предпосылка → скажи».
- `lab/Modelfile.agent` — то же, но ctx 64k и запасной SYSTEM (OpenCode передаёт свой system prompt, этот работает при прямом чате).
- `lab/demo/opencode.json` — провайдер Ollama через OpenAI-совместимый `/v1`, модель `itmo-agent` с `reasoningEffort: "none"`; два агента `local-guide` (промпт `demo/repo-system.txt`, дополнен подсказкой искать по всем файлам) и `local-qwen`, оба **только на чтение** (`"*": "deny"`, разрешены `read`, `glob`, `grep`, `list`).
- `make test` из `practices/practice_03` проходит (3 теста).

## Проблемы, с которыми столкнулся

1. **Обрезка контекста.** С дефолтными 4096 токенами Ollama обрезает промпт OpenCode до ~2k токенов, и модель теряет инструкции. Решение: отдельная модель с `num_ctx 65536`.
2. **Скрытый thinking.** qwen3.5 по умолчанию «думает», через `/v1` OpenCode этого не показывает, но ответ идёт минуты. `options.reasoningEffort: "none"` — ответ за 0.7 с вместо 24 с на простом запросе.
3. **Модель для заголовков сессии.** Если `small_model` не задан, OpenCode берёт другую модель, Ollama перегружает модели в памяти и основной запрос ждёт ~2 мин. Решение: `small_model` = та же `itmo-agent`.
4. **`opencode run` зависал** при открытом stdin (запуск из скрипта) — нужно `< /dev/null`.

## Ограничения и выводы

- 4B-модель **находит факты, но ленится искать**: на вопрос 1 открыла один файл и не заглянула в `Makefile`/`README`. Качество ответа зависит от того, какие файлы агент решит прочитать.
- **Ответы нестабильны между запусками.** При повторном прогоне вопроса 3 модель один раз искала только `*.js`/`*.ts` и ничего не нашла. После подсказки в `demo/repo-system.txt` («начинай с glob `**/*`, grep без фильтра по типу») 4 прогона из 4 дали верный вывод, но в 2 из них модель выдумала детали: «unsubscribe используется в тесте», «opencode.json содержит задачу». Вывод верный, а обоснованию верить без проверки нельзя.
- Встречаются языковые артефакты (китайское слово посреди русского ответа) и лишняя аргументация.
- System prompt реально работает: без него модель добавляет «наверное, GitHub Actions», с ним — честное «нет ответа», и ответ в 2.6 раза короче.
- Read-only права — обязательны: модель маленькая и может ошибиться в действии, а так она физически не может ничего изменить или запустить.
- Для маленького демо-репозитория локальная модель годится как справочник «где это в коде», для реальной разработки (правки, многошаговые задачи) — слабовата и медленная (~15–20 с на простой вопрос).
