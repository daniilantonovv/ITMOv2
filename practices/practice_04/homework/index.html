Б. Свой skill: collection-approval 2 балла

Устройство и автоматизация

Ключевой сценарий из ТЗ — «агент сохраняет подборку только после явного апрува» — оформлен как процедура из 5 шагов с жёсткими правилами: одно «да» — одна подборка; правка обнуляет одобрение; данные не «чинятся» ради валидации. Файлы: SKILL.md, scripts/preview.py, examples/dinner.json.

preview.py переиспользует модели сервиса (app/models.py) — валидация ровно та же, что у API, без копии правил. Он проверяет дубликат по живому API и печатает чек для оператора. Коды выхода управляют следующим шагом: 0 — спросить оператора, 1 — невалидно, не показывать, 2 — уже сохранена. Покрыт 4 тестами (tests/test_skill_preview.py).

Реальный запуск и проверенный результат

Полный проход на живом сервисе — evidence/skill-run.txt:

$ preview.py data/pending/pasta.json
Подборка: Паста за 20 минут
  Спагетти................... 1 × 129,00 ₽ = 129,00 ₽
  Томаты в собственном соку.. 1 × 159,00 ₽ = 159,00 ₽
  Пармезан 150 г............. 1 × 399,00 ₽ = 399,00 ₽
Итого: 687,00 ₽
Сохранить эту подборку на дашборд? Ответьте «да» или опишите правки.   exit 0

# оператор ответил «да» → save_collection(operator_approved=true) → id 12

$ preview.py data/pending/pasta.json        # повторно
Эта корзина уже сохранена: подборка №12 «Паста за 20 минут».           exit 2

Испорченные данные (отрицательная цена, ссылка без https) — exit 1 с путями полей, до оператора не доходят. Первый запуск при выключенном сервисе дал предупреждение «не удалось проверить дубликаты» — сценарий из SKILL.md отработал как задуман.

В. Свой MCP: collections 2 балла

Полезный tool

mcp_server/server.py (MCP Python SDK 2.3, stdio). save_collection сохраняет подборку в сервис через его HTTP API — API остаётся единственным местом валидации. Без operator_approved=true отказывает сам. Ошибки HTTP переводит в понятные агенту сообщения: 409, 422 (с путями полей), 503, недоступность и таймаут. Второй tool, list_collections, — проверка уже сохранённого.

Вызов и результат, включая ошибочный вход

Реальные вызовы по stdio в отдельном процессе — так же, как запускает OpenCode — против живого сервиса: evidence/mcp-stdio-calls.txt.
