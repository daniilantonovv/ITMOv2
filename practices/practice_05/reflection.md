# Рефлексия по ДЗ 5

Главный урок этой работы для меня — договориться об одном контракте между UI и API до генерации кода. Две подробные спецификации ещё не означают, что части системы совместимы: UI-черновик предлагал параметр `search`, поиск по продуктам и `total_count`, а backend-черновик — `q`, поиск только по названию и другой состав ответа. Без общего контракта эти расхождения обнаружились бы уже при соединении готовых частей.

Общий контракт помог сделать решения конкретными: искать только в `title`, сохранить прежний `CollectionSummary[]`, объединять запрос с категорией и применять фильтр до `limit`. Для русского регистра и буквальных `%`/`_` недостаточно просто написать `LIKE`. При существующем ограничении в 100 подборок фильтрация через Python `casefold()` решает задачу без новой библиотеки и миграции. Здесь ценность SDD для меня в том, что такие решения становятся видимыми и проверяемыми до реализации, а не теряются в отдельных запросах к агенту.

Проверки показали связь между контрактом и результатом: сначала новые тесты дали 14 failures, после реализации все 80 проверок прошли. Браузер отдельно проверил повтор после сетевого отказа, устаревшие ответы и границу Unicode; одни HTTP-тесты не покрывали бы поведение интерфейса. Из сравнения со Spec Kit и OpenSpec я вынес, что форма документов и команды CLI помогают организовать работу, но не заменяют согласование смысла. Для следующей похожей задачи основной ориентир — сначала общий контракт с примерами ответов, ошибок и границ, затем реализация обеих частей и их совместная проверка.
