# Рефлексия по ДЗ 5

Два независимых черновика оказались несовместимыми: UI предлагал search, продукты и total_count, а backend — q, только title и даже урезанный ответ collection_id/title. Общий контракт убрал эти расхождения до правок приложения. Отдельно пришлось уточнить русский регистр, буквальные %/_, порядок «фильтр → limit» и пустую выдачу. Модель backend предложила LIKE, хотя обычный SQLite не обеспечивает нужный casefold; в проекте максимум 100 записей, поэтому небольшой фильтр в Python оказался достаточным.

Полезная часть SDD — сопоставить каждое решение с проверкой, а не объём документов. 14 новых сценариев сначала упали; после реализации все 80 тестов зелёные. В браузере отдельно проверены сетевой отказ, повтор, старый успешный и старый неуспешный ответ: HTTP-тесты сами по себе не заметили бы перерисовку устаревших карточек. Spec Kit дал понятную последовательность constitution/spec/plan/tasks, но его CLI не проверяет смысл спецификации. Если продолжать проект, следующий полезный шаг — автоматизировать эти реальные браузерные сценарии в уже согласованном окружении, а не добавлять новые поисковые возможности без необходимости.

Это техническая рефлексия исполнителя. Личная оценка студента и окончательная приёмка человеком здесь не выдуманы.
