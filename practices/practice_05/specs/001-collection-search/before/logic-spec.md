**Задача:** Добавить функционал поиска (`GET /api/collections?q=...`) в существующий endpoint для API VkusVill Collections на FastAPI с SQLite.

**Входные данные:**
- **Endpoint:** `GET /api/collections` (с сохранением params `?limit=&category=`).
- **Параметр поиска:** `q` (запрос по заголовку/параметру).
- **Логика обработки запроса:**
  1. **Проверка长度的:** Получить длину строки в `q`. Если длина > 120 символов — вернуть ошибку HTTP 422 (`title`, `Unicode` не поддерживается, `case-insensitive`, `literal substring`, `trim`).
  2. **Логика поиска:**
     - Если `q` пустой → сохранить текущее поведение (сортировка по `summary[] newest first`, лимит 100).
     - Если `q` не пустой:
       - Искать только в поле `title`.
       - Использовать Unicode подстроку, нечувствительную к регистру.
       - Применить `trim`.
       - Запрашивать **только** записи, удовлетворяющие условию поиска (`title LIKE ...`).
       - После фильтрации искать (если нужно) и applying лимит (предполагается, что поиск сам ограничивает объем данных или фильтр по 100 записей).
  3. **Вывод:** Поля `title` (остальные поля без изменений, только `title`).
- **API:**
  - Успешный ответ: `200 OK`, JSON список с полями `collection_id`, `title`.
  - Ошибка валидации (длинный запрос): `422 Unprocessable Entity`.
  - Серверная ошибка (storage): `503 Service Unavailable`.
- **Ограничения:**
  - Никаких новых библиотек.
  - Нет новых эндпоинтов.
  - Не влияют на существующую логику `summary[]` (сортировка/преобразование).
