# Chain of Verification

- Проверяемый черновик или утверждение: разделы «Факты и правила» и «Формат входа и результата» в [`practice_01/context.md`](../../practice_01/context.md) — 18 утверждений о строках diff, правилах и кодах ответа.

Инструмент: OpenCode 1.18.29, `vsellm/openai/gpt-5`, agent `plan`, вложения: `context.md`, `TRAINING_PR.diff`, `CASE.md`.

## Запрос на проверку

```text
Chain of Verification. Проверяемый черновик — раздел «Факты и правила» и «Формат входа и результата» в приложенном context.md. Единственный источник истины — приложенный TRAINING_PR.diff и CASE.md.
Шаг 1. Выпиши каждое фактическое утверждение черновика о коде (файл, номер строки, поведение) и о правилах.
Шаг 2. Для каждого утверждения задай один проверочный вопрос, ответ на который можно получить только из diff или CASE.md (например: «Какая строка новой версии app/api.py содержит payload["diff"]?»).
Шаг 3. Ответь на каждый вопрос независимо от черновика, процитировав строку-источник. Номер строки считай по содержимому hunk (строки контекста и «+»), начиная с номера из заголовка hunk.
Шаг 4. Верни исправленный текст раздела только для утверждений, которые не подтвердились или сформулированы неточно.
Формат: таблица «Утверждение | Вопрос | Источник (цитата) | Результат: подтверждено / опровергнуто / не проверяемо по diff», затем «Исправления:» списком. Рассуждения не выводи.
```

## Вопросы проверки и evidence

Полный ответ — [`result.md`](result.md). Сокращённо:

| Вопрос | Источник или проверка | Результат |
|---|---|---|

| Какие строки `app/review_service.py` содержат f-string с diff и `{"comment": answer}`? | diff: `app/review_service.py:13–16` | подтверждено |
| Откуда импортируется `review_service`, есть ли модуль в diff? | diff: `app/api.py:3`; в diff только 2 файла | подтверждено |
| Как сформулированы SEC-1, API-1, REL-1, OUT-1, SCOPE-1, QA-1, OBS-1? | CASE.md, раздел «Правила репозитория» | подтверждено (7 из 7) |
| Вход: ключ `diff`, тип `str`, лимит 20 000 | diff `app/api.py:10`, `app/review_service.py:13`; API-1 | подтверждено |
| Где задан код 422 при отсутствии/неверном типе `diff`? | — | **не проверяемо по diff** |
| Где заданы 504/503 и «тело без текста diff»? | REL-1 говорит только «контролируемый ответ» | **не проверяемо по diff** |

Итог: 16 утверждений подтверждены, 2 не следуют из источников.

## Исправленный результат

Модель предложила удалить из «Формат входа и результата» коды 422, 504/503 и требование «тело без текста diff», оставив только 413 (API-1) и «контролируемый ответ» (REL-1).

## Что изменили в исходном артефакте

- Файл и раздел: [`practice_01/context.md`](../../practice_01/context.md) → «Формат входа и результата».
- Изменение: ошибки разделены на «заданные правилами» (413 — API-1; контролируемый ответ — REL-1) и «выбранные нами» (422, 504/503, тело без diff) со ссылкой на [`adr.md`](../../practice_01/adr.md). Добавлен факт: `diff: str` в `review_service.py:13` — только аннотация, `api.py:9` принимает `dict`, тип не проверяется. Это слабое место, которое CoVe засчитал как «подтверждено».
- Что отклонили: удаление 422 и 504/503. Это осознанные проектные решения ADR-001, их нужно пометить как решения, а не удалять.
