# RAG

- Вопрос к источникам: какие правила репозитория (SEC-1…OBS-1) покрыты проверками и на каких уровнях, где пробелы?

Инструмент: OpenCode 1.18.29, `vsellm/openai/gpt-5`, agent `plan`. «Retrieval» — ручной: модели переданы только перечисленные файлы, запуск в папке без остального репозитория.

## Запрос

```text
Отвечай ТОЛЬКО по приложенным источникам: CASE.md (раздел «Правила репозитория»), tests_unit.md, tests_integration.md, tests_e2e.md, tests_load.md. Других знаний о проекте не используй. Каждое утверждение сопровождай ссылкой вида [файл#ID-проверки] или [CASE.md#ПРАВИЛО].
Вопрос: какие правила SEC-1, API-1, REL-1, OUT-1, SCOPE-1, QA-1, OBS-1 покрыты проверками и на каких уровнях (unit / integration / e2e / load), а какие не покрыты или покрыты только частично?
Формат: таблица «Правило | Unit | Integration | E2E | Load | Пробел» (в ячейках — ID проверок), затем список «Предлагаемые проверки для пробелов» — не больше трёх, каждая со ссылкой на правило-источник. Если утверждение нельзя подтвердить источником — пиши «нет в источниках».
```

## Ответ со ссылками на источники

Полный ответ — [`result.md`](result.md). Матрица покрытия:

| Правило | Unit | Integration | E2E | Load | Пробел по модели |
|---|---|---|---|---|---|
| SEC-1 | U-01, U-02 | INT-04 | E2E-04 | — | Load |
| API-1 | U-03, U-04 | INT-05 | E2E-03 | L-03 | — |
| REL-1 | — | INT-02 | — | L-02 | Unit, **E2E** |
| OUT-1 | U-05, U-07 | INT-01 | E2E-01 | — | Load |
| SCOPE-1 | — | — | — | — | **Нет ни одной проверки** |
| QA-1 | U-06 | INT-03 | E2E-01 | — | Load |
| OBS-1 | — | INT-04 | E2E-02, E2E-04 | L-01 | Частично |

Модель предложила 3 проверки: E2E для REL-1; нагрузочный прогон с канареечными секретами (SEC-1, OBS-1); проверку отсутствия побочных действий (SCOPE-1). Каждая ссылка — на ID в источнике.

## Что изменили в исходном артефакте

- Файл и раздел: [`practice_01/tests_integration.md`](../../practice_01/tests_integration.md) → строка INT-06 (SCOPE-1: единственный исходящий вызов — к LLM, 0 запросов к GitHub, инструкция «approve and merge» из diff не исполняется); [`practice_01/tests_e2e.md`](../../practice_01/tests_e2e.md) → строка E2E-05 (REL-1 через Toxiproxy: 504 за ≤ 11 с, 503 при обрыве).
- Как проверили ссылки: в ответе 34 ссылки, 26 уникальных ID; каждый нашли поиском в соответствующем файле, несуществующих нет.
- Также закрыт пробел «REL-1, Unit»: добавлена проверка U-11 — адаптер LLM превращает таймаут в `LLMTimeout` (504), ошибку провайдера в `LLMUnavailable` (503).
- Что отклонили как неподтверждённое: нагрузочный прогон с секретами — SEC-1 детерминированно покрыт U-01 и INT-04, нагрузка ничего не добавит. «Пробел Load» для OUT-1 и QA-1 тоже не закрываем: это не нагрузочные свойства. Пометку «OBS-1 частично» (в логах под нагрузкой не проверяли отсутствие diff) принимаем как есть: L-01 уже читает поля лога, а отсутствие diff в логе детерминированно проверяет INT-04 — под нагрузкой формат записи тот же.
